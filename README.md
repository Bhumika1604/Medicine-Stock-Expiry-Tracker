# Medicine Stock & Expiry Tracker

A full-stack Laravel inventory management system for pharmacies, medical stores, and
hospital dispensaries — built to track medicines batch-by-batch, with automatic
stock and expiry status, dashboards, reports, and CSV export.

> **⚠️ Important note on how this project was produced:** this codebase was generated by
> an AI assistant running in a sandboxed environment **without PHP, Composer, or MySQL
> installed, and without network access to Packagist**. That means the code below has
> been written to correct, idiomatic Laravel 11 conventions but **has not been executed,
> migrated, or tested end-to-end by the assistant**. Before you treat this as
> production-ready, run through the Installation and Troubleshooting sections and
> smoke-test the main flows (login → add medicine → add batch → update stock → reports)
> yourself. The included PHPUnit tests will catch most integration issues once you run
> `php artisan test`.

---

## Project Overview

MediTrack lets an admin:

- Manage **categories** and **medicines**
- Track **batch-wise stock**: batch number, manufacturing/expiry dates, quantity,
  minimum stock level, pricing, supplier
- Auto-compute **stock status** (In Stock / Low Stock / Out of Stock) and **expiry
  status** (Valid / Near Expiry / Expired) — nothing is hardcoded
- Add/remove stock with full **transaction history** (IN / OUT / ADJUSTMENT)
- View a live **dashboard** with Chart.js charts, alerts, and recent activity
- **Search, filter, sort, and paginate** medicines, batches, and history
- Generate **Inventory / Expiry / Stock reports** with filters and **CSV export**
- Configure **Settings** (org name, near-expiry threshold, default min stock, currency)

## Roles & Permissions

Three roles now exist. `role` and `is_active` were added to the `users` table via an
**additive** migration (`2025_02_01_000001_add_role_and_status_to_users_table.php`) —
the original `users` migration is untouched.

| Area | Admin | Pharmacist | Staff |
|---|:---:|:---:|:---:|
| View dashboard, medicines, stock history, expiry alerts, out-of-stock | ✅ | ✅ | ✅ |
| Record stock in/out/adjustment | ✅ | ✅ | ✅ |
| Create/edit/delete medicines & batches | ✅ | ✅ | ❌ |
| Manage categories | ✅ | ❌ | ❌ |
| View/export reports | ✅ | ✅ | ❌ |
| Settings | ✅ | ❌ | ❌ |
| User Management | ✅ | ❌ | ❌ |
| Own profile (info + password) | ✅ | ✅ | ✅ |

Enforced via a small `role:admin,pharmacist` route-middleware alias
(`App\Http\Middleware\EnsureUserHasRole`, registered in `bootstrap/app.php`) — existing
controllers were **not modified** to add this; only `routes/web.php` groups routes
under the appropriate `role:` middleware. Views additionally hide buttons a role can't
use (e.g. Staff never sees "Edit"/"Delete" on a medicine), as defense-in-depth on top
of the route-level checks — a direct URL hit still gets a proper 403.

New self-registrations (`/register`) always get the **Staff** role — the role/status
fields are deliberately hardcoded in `AuthController::register()`, never mass-assigned
from the request, so a visitor can't grant themselves elevated access.

## Installation

```bash
# 1. Get the code onto your machine (unzip the provided archive, or clone your repo)
cd medicine-stock-tracker

# 2. Install PHP dependencies
composer install

# 3. Install JS dependencies and build assets
npm install
npm run build          # or `npm run dev` while developing

# 4. Environment
cp .env.example .env
php artisan key:generate

# 5. Configure MySQL in .env (see below), then create the database
mysql -u root -p -e "CREATE DATABASE medicine_tracker CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 6. Migrate + seed
php artisan migrate --seed

# 7. Serve
php artisan serve
```

Visit **http://localhost:8000** — you'll be redirected to `/login`.

## Database Structure

- **categories** — `id, name, description, status, timestamps`
- **medicines** — `id, category_id (FK), name, generic_name, manufacturer, dosage_form, strength, description, timestamps, soft-deletes`
- **batches** — `id, medicine_id (FK), batch_number, manufacturing_date, expiry_date, quantity, minimum_stock_level, purchase_price, selling_price, supplier_name, timestamps` — unique on `(medicine_id, batch_number)`
- **stock_transactions** — `id, batch_id (FK), user_id (FK), transaction_type [IN|OUT|ADJUSTMENT], quantity, previous_quantity, new_quantity, reason, timestamps`
- **settings** — simple `key`/`value` store for the Settings page (pharmacy name, near-expiry days, default min stock, currency symbol)
- **users** — original Laravel fields **plus** `role` (`admin`/`pharmacist`/`staff`, default `staff`) and `is_active` (boolean, default `true`), added via a separate additive migration

Stock status and expiry status are **never stored** — they're computed on the fly by
`Batch::getStockStatus()` and `Batch::getExpiryStatus()` (and mirrored as query scopes:
`outOfStock()`, `lowStock()`, `inStock()`, `expired()`, `nearExpiry()`, `valid()`), so
the dashboard, lists, alerts, and reports can never drift out of sync.

## Troubleshooting

- **"SQLSTATE[HY000] [2002] Connection refused"** — MySQL isn't running or the
  host/port in `.env` is wrong. Confirm with `mysql -u root -p -h 127.0.0.1`.
- **"Unknown database 'medicine_tracker'"** — you skipped the `CREATE DATABASE` step
  above.
- **Vite manifest not found / styles look unstyled** — run `npm install && npm run build`
  (or `npm run dev` in a second terminal while developing).
- **419 Page Expired on login** — clear cookies / restart `php artisan serve`, and make
  sure `APP_KEY` was generated (`php artisan key:generate`).
- **Charts don't render** — the dashboard loads Chart.js from a CDN
  (`cdnjs.cloudflare.com`); if you're on a fully offline network, swap that `<script>`
  tag in `resources/views/dashboard/index.blade.php` for a local/npm-bundled copy.
- **Permission errors on `storage/` or `bootstrap/cache/`** — `chmod -R 775 storage bootstrap/cache` on Linux/macOS.
